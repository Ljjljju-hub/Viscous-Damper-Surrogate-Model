# COMSOL 自动续算使用说明

## 1. 适用范围

本文档用于完成 `4_Combined_Master_Dataset.json` 中尚未计算的 COMSOL 工况，并自动将 COMSOL 导出的 VTU 转换为训练使用的 HDF5。

脚本默认按顺序串行运行，不会同时启动多个 COMSOL 求解任务。每一批使用独立 Python 进程、独立 COMSOL client-server 会话和独立终端；一批结束后全部退出，再启动下一批，以释放 COMSOL 和 JVM 占用的内存。

主要入口：

```text
run_remaining.py        自动调度全部剩余工况
main.py                 单批 COMSOL worker，不建议手工批量调用
failure_registry.py     恢复并维护失败工况清单
transfer2hdf5.py        VTU -> HDF5 增量转换
运行剩余工况.bat       固定使用本机 conda pinn 环境的快捷入口
```

## 2. 运行前检查

### 2.1 必要文件

确认以下文件位于 `计算有限元数据` 目录：

```text
standard_model.mph
4_Combined_Master_Dataset.json
main.py
run_remaining.py
failure_registry.py
transfer2hdf5.py
```

### 2.2 Python 环境

后续统一使用 conda `pinn` 环境：

```powershell
conda activate pinn
python -c "import mph, pyvista, h5py; print(mph.__version__)"
```

本机快捷脚本固定调用：

```text
D:\Aanconda3\envs\pinn\python.exe
```

如果 conda 安装位置改变，需要同步修改 `运行剩余工况.bat` 中的 `PINN_PYTHON`。

### 2.3 COMSOL 条件

- COMSOL 必须已经正确安装，并能被 MPh 检测到。
- 当前 Windows 用户必须能正常取得所需 COMSOL license。
- 正式运行前建议关闭手工打开但不再使用的 COMSOL 会话，避免额外占用 license 和内存。
- 确保磁盘同时容纳 VTU 和 HDF5；自动流程不会删除原始 VTU。

## 3. 首次运行

在仓库根目录打开 PowerShell，先执行计划检查：

```powershell
conda activate pinn
python .\计算有限元数据\run_remaining.py --dry-run
```

`--dry-run` 校验现有 VTU/HDF5，并从历史 worker 日志同步失败清单；它不启动 COMSOL、不转换结果文件。

应重点确认终端中的四项统计：

```text
参数工况总数
有效 HDF5 数量
已失败且默认跳过的数量
需要 COMSOL 计算的数量
```

2026-08-08 的项目快照为：总计 1000 个、有效 HDF5 870 个、明确失败并跳过 36 个、待 COMSOL 计算 94 个。该数字会随着计算推进而变化，应以每次 `--dry-run` 的结果为准。

## 4. 正式启动

推荐初始设置：

```powershell
python .\计算有限元数据\run_remaining.py --batch-size 10 --cores 16 --max-retries 2 --pause-seconds 10
```

或者直接使用快捷入口：

```powershell
& '.\计算有限元数据\运行剩余工况.bat' --batch-size 10 --cores 16 --max-retries 2
```

正式运行时有两类终端：

1. **控制器终端**：始终保留，用来检查完成状态并启动下一批。
2. **worker 终端**：每批新建，当前批退出后自动关闭。

不能让所有终端同时退出后再自动启动下一批，因为必须有一个控制器进程保存调度流程。真正需要隔离和退出的是持有 COMSOL/JVM 的 worker 进程。

## 5. 参数说明

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--batch-size` | 10 | 单个 COMSOL 进程计算的工况数 |
| `--cores` | 16 | 单个 COMSOL 会话使用的 CPU 核心数 |
| `--max-retries` | 2 | worker 崩溃、超时或转换失败等未记录 case 失败时的额外重试次数 |
| `--pause-seconds` | 10 | 相邻 COMSOL 批次之间的等待时间 |
| `--timeout-minutes` | 0 | 单批最长时间，0 表示不限制 |
| `--first-case` | 1 | 处理范围的第一个 JSON 序号，包含 |
| `--last-case` | 1000 | 处理范围的最后一个 JSON 序号，包含 |
| `--dry-run` | 关闭 | 仅输出计划 |
| `--no-worker-window` | 关闭 | worker 在后台运行，不显示独立窗口 |
| `--no-convert` | 关闭 | 只产生 VTU，不自动转换 HDF5 |
| `--retry-failed` | 关闭 | 显式重算 `failed_cases.json` 中的工况；默认不重算 |

`--first-case` 和 `--last-case` 是 JSON 中的 1-based 顺序，不是 Python 的半开区间。例如：

```powershell
python .\计算有限元数据\run_remaining.py --first-case 305 --last-case 500 --batch-size 5
```

会检查并续算第 305 到第 500 个工况，两个端点都包含。

## 6. 批大小选择

建议先用 2 到 5 个工况验证一批完整运行：

```powershell
python .\计算有限元数据\run_remaining.py --first-case 305 --last-case 309 --batch-size 5 --cores 16
```

确认 COMSOL 求解、VTU 导出、终端关闭和 HDF5 转换均正常后，再运行全部剩余工况。

经验选择：

| 情况 | 建议 `batch-size` |
|---|---:|
| 内存非常紧张或模型偶发崩溃 | 1-2 |
| 首次正式运行 | 5 |
| 已验证稳定 | 10 |
| 内存充足且长批次稳定 | 20 |

批大小只影响多久彻底重启一次 COMSOL，不改变工况内容和结果。

## 7. 中断与恢复

### 7.1 正常停止

在**控制器终端**按 `Ctrl+C`。控制器会终止当前 worker 进程树，并以退出码 130 结束。

已经完成并原子发布的 VTU/HDF5 会被保留。临时 `.partial` 文件不会被当作完成结果。

### 7.2 恢复运行

重新执行原来的正式运行命令即可，不需要手工填写起始 case：

```powershell
python .\计算有限元数据\run_remaining.py --batch-size 10 --cores 16 --max-retries 2 --pause-seconds 10
```

控制器会重新扫描全部工况：

- HDF5 有效：跳过。
- HDF5 缺失但 VTU 完整：只做转换。
- HDF5 和 VTU 都不完整，且未记录失败：重新运行 COMSOL。
- worker 日志中已经明确计算失败：写入 `failed_cases.json` 并跳过。

### 7.3 worker 窗口被关闭

如果误关了当前 worker 窗口，控制器会收到非零退出码。本批已完成的原子输出仍然有效；没有产生明确 case 失败日志的缺失项会在后续重试中重新识别。

## 8. 输出与日志

### 8.1 数据目录

```text
comsol_output/       COMSOL 导出的 Case_XXXX.vtu
comsol_hdf5/         转换后的 Case_XXXX.h5
```

### 8.2 日志目录

```text
batch_logs/controller_时间_PID.log
batch_logs/worker_首工况_末工况_时间_PID.log
```

控制器日志用于判断批次启动、退出码、转换和重试情况。worker 日志包含每个 case 的参数注入、求解耗时和完整异常堆栈。

`failed_cases.json` 是结构化失败清单。控制器首次运行新逻辑时会扫描历史 `batch_logs/worker_*.log`，自动恢复其中明确记录的失败工况；成功生成有效 VTU/HDF5 后，对应失败标记会自动移除。

### 8.3 状态文件

`batch_state.json` 在每批前后原子更新，主要字段包括：

```text
status
python
pass_number
current_batch
total
hdf5_completed
vtu_waiting_for_conversion
failed_terminal
pending_comsol
unresolved
```

`status` 常见值：

| 值 | 含义 |
|---|---|
| `running` | worker 正在运行 |
| `between_batches` | 当前批已退出，准备下一批 |
| `interrupted` | 用户中断 |
| `controller_error` | 控制器发生异常 |
| `incomplete` | 达到重试上限仍有未形成终态记录的缺失项 |
| `complete_with_failures` | 可计算队列已完成，只剩被明确记录并跳过的失败工况 |
| `complete` | 所选范围全部完成 |

日志、状态文件和失败清单均已加入 `.gitignore`。

## 9. 退出码

### 9.1 控制器 `run_remaining.py`

| 退出码 | 含义 |
|---:|---|
| 0 | 全部完成，或 dry-run 正常结束 |
| 1 | 仍缺少 HDF5，包括只剩明确失败并跳过的情况 |
| 2 | 参数、环境或控制器运行错误 |
| 130 | 用户按 `Ctrl+C` 中断 |

### 9.2 worker `main.py`

| 退出码 | 含义 |
|---:|---|
| 0 | 本批全部成功或已有有效输出 |
| 1 | 本批至少一个 case 求解失败 |
| 2 | worker 启动、参数或 COMSOL 会话错误 |

## 10. 常见问题

### 10.1 提示当前不是 pinn 环境

执行：

```powershell
conda activate pinn
```

或者改用 `运行剩余工况.bat`。

### 10.2 COMSOL 内存仍然过高

先把批大小降为 2 或 1：

```powershell
python .\计算有限元数据\run_remaining.py --batch-size 2 --pause-seconds 30
```

检查 worker 日志中是否出现“COMSOL 会话已关闭，worker 即将退出”。若 worker 超时不退出，可设置 `--timeout-minutes`，控制器会调用 Windows `taskkill /T /F` 终止整个 worker 进程树。

### 10.3 某几个 case 一直失败

查看对应 worker 日志中的 COMSOL 异常。失败工况默认不会再次进入自动队列。可以单独调试：

```powershell
python .\计算有限元数据\main.py --case-ids Case_0305 --cores 16
```

单独运行 `main.py` 仍然只应处理少量 case；完成后该 Python 进程必须退出。

确认模型或参数已经修改、需要通过控制器重新验证失败工况时，显式运行：

```powershell
python .\计算有限元数据\run_remaining.py --retry-failed --batch-size 1
```

不带 `--retry-failed` 的正常续算永远不会调度这些失败工况。

### 10.4 有 VTU 但没有 HDF5

重新运行控制器即可自动补转换，也可以手工执行：

```powershell
python .\计算有限元数据\transfer2hdf5.py --case-ids Case_0305
```

### 10.5 输出文件存在但仍被重新计算

脚本不会只依据文件名判断完成。体积过小、VTU 缺少结束标签、HDF5 缺少数据集或字段形状不一致，都会被视为损坏结果并重新处理。

## 11. 测试

自动化测试不启动 COMSOL：

```powershell
conda activate pinn
python -m unittest discover -s .\计算有限元数据 -p "test_*.py" -v
```

测试覆盖参数选择、分批、失败清单恢复与跳过、COMSOL 参数单位、client/server 关闭、输出有效性判断和 VTU 到 HDF5 原子转换。
